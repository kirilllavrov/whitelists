# Whitelist RU

Проверка доменов и IP на прохождение через белый список мобильного оператора.

Работает через USB-модем: поднимает изолированный `macvlan`-контейнер на интерфейсе модема, чтобы маршруты хоста и обычный интернет не затрагивались. Можно пользоваться при активном VPN и не бояться, что трафик уйдёт не туда.

## Требования к окружению

Инструмент — это папка `tools/whitelist-probe` целиком (4 файла: `whitelist-probe`, `probe.py`, `Dockerfile`, `net-guard`). Скопируйте её, остальное соберётся само.

| Требование | Почему |
| --- | --- |
| Linux | используются `iproute2`, `/dev/tcp`, `/sys/class/net` |
| Docker **rootful** | rootless не умеет `macvlan` |
| Пользователь в группе `docker` | иначе нужен sudo, а скрипт его не просит |
| USB-модем или USB-тетеринг | macvlan поверх Wi-Fi обычно не работает: точка доступа отбрасывает кадры с чужим MAC. Скрипт предупредит, если интерфейс беспроводной |
| Интернет при первой сборке | база `alpine:3.20` тянется из реестра |

Docker Desktop на macOS и Windows **не подходит**: там нет `macvlan` с родительским интерфейсом. Нужна Linux-машина или Linux-VM с проброшенным USB-модемом.

Другой адрес модема (не `192.168.8.1`) — укажите `--gateway 192.168.1.1` или `WLP_GATEWAY=...`. Подсеть и интерфейс определяются сами. Перед запуском идёт проверка: если шлюз не отвечает ни по ICMP, ни по TCP:80, скрипт остановится, а не станет молча проверять через обычный интернет.

Устройство контейнера: ему выдаётся статический адрес `.250–.253` в подсети модема. Если подсеть не /24 (например, `172.20.10.0/28` у iPhone), используются четыре последних адреса перед broadcast, кроме шлюза и адреса хоста. Если модем раздаёт только одному клиенту или режет неизвестные MAC, ни один адрес не поднимется — тогда нужен другой способ (например, туннель с телефона).

### Ограничения

- `--jobs > 1` плохое решение: модем под параллельной нагрузкой рвёт соединения, получаются ложные `blocked_*`. По умолчанию 1.
- Проверяются только A-записи, IPv6 не поддерживается.
- `blocked_timeout` — не установилось TCP-соединение, `blocked_tls_timeout` — TCP есть, но TLS-рукопожатие молчит. Оба могут означать как блокировку, так и молчание/защиту на стороне сервера. Если адрес подозрительный, проверьте его повторно с разными `--sni`: блокировка по IP не зависит от SNI.
- Список адресов домена — снимок текущих DNS-ответов. У CDN он меняется.

## Быстрый старт

```bash
cd tools/whitelist-probe

./whitelist-probe doctor   # модем и docker на месте
./net-guard fix            # маршруты хоста не смотрят в модем
./whitelist-probe check    # src/domains проекта, всё в checks/
```

```bash
../whitelist-merge/whitelist-merge   # пересечение всех прогонов -> release/
```

`check` без аргументов берёт домены из `src/domains` проекта (для копии инструмента — `../../src/domains`). Явный путь тоже работает: `./whitelist-probe check ../../src/domains`.

Каталог прогона получает штамп времени и имя оператора, например `checks/2026-01-01_214500_megafon/`. Что внутри — в разделе [Результат прогона](#результат-прогона).

## Как это работает

### Домен

1. Все A-записи через DNS модема (`dig +noedns`). Пока адресов нет, а сервер не ответил или ответил ошибкой (`SERVFAIL`, `REFUSED`), запрос повторяется, всего до 4 попыток. Если DNS так и не ответил — `dns_error`, и второй проход проверит домен заново, начиная с DNS. Пустой ответ или `NXDOMAIN` — окончательное `no_dns`.
2. Если все ответы — заглушки (`8.6.112.*`, `8.47.69.*`, `0.0.0.0`, `127.0.0.1`), статус `blocked_dns`.
3. **Первый проход** — по каждому адресу TCP:443 и TLS-рукопожатие с SNI этого домена. Рукопожатие делает клиент с отпечатком Chrome (`curl_cffi`): обычный Python-SSL часть банков молча блокирует на несколько минут, и тогда прогон видит `blocked_timeout` там, где браузер открывает сайт. Если `curl_cffi` в образе не установился, инструмент откатывается на стандартный `ssl`. Тело ответа не читается — важен только факт состоявшегося рукопожатия, поэтому серверы с необычным `Content-Encoding` (например, `aws-chunked` у `sber.ru`) доступны, а не падают в `error`. По умолчанию проверяются все A-записи, `--max-ips N` ограничивает их число. `--first-ip` останавливается на первом рабочем — быстрее, но в списке IP будет по одному адресу на домен.
4. Если TLS не прошёл — сразу запрос по HTTP:80. Потому что портал оператора виден только там: по 443 блокировка выглядит как обычный таймаут. Редирект на страницу оператора даёт терминальный `blocked_portal`, живой ответ — `open_http` или `http_redirect`. Это тот же проход: прерванный прогон успевает показать порталы, а не только таймауты.
5. **Второй проход** — только для неоднозначных отказов, в том числе `dns_error`: такие домены проверяются заново целиком, с DNS. TLS повторяется с утроенным таймаутом (`--retries`, по умолчанию два раза): на мобильном канале первый отказ часто оказывается потерей пакета, а не блокировкой. Если TLS прошёл — статус становится `allow`, иначе остаётся результат первого прохода. `--no-second-pass` или `--retries 0` отключают этот проход.
6. Между целями выдерживается пауза `--delay` (0.3 с, со случайным разбросом) — чтобы не долбить модем и его DNS в упор. `--delay 0` отключает.

### IP

Первый проход — TLS-рукопожатие на 443 с SNI из `--sni`, при неудаче HTTP:80 с тем же `Host`; второй — медленный повтор TLS, как у доменов.

### Статусы

| Статус | Значение |
| --- | --- |
| `allow` | TLS прошёл, сайт доступен |
| `allow_tls` | TCP и TLS есть, сервер ответил, но сам прервал рукопожатие (alert, сертификат) — не блокировка |
| `open_http` | 443 закрыт, но по 80 отдаётся ответ (не редирект на https) |
| `http_redirect` | по 80 редирект на `https://`, куда доступа нет — практически недоступен |
| `blocked_portal` | по 80 редирект на страницу оператора «Доступ ограничен» |
| `blocked_dns` | DNS вернул заглушку |
| `blocked_tls` | RST во время TLS или соединение закрыто до ответа сервера |
| `blocked_timeout` | TCP-соединение не установилось (таймаут) |
| `blocked_tls_timeout` | TCP есть, но TLS-рукопожатие не завершилось (таймаут) |
| `refused` | соединение отклонено |
| `no_dns` | A-записей нет: DNS ответил `NOERROR` без адресов или `NXDOMAIN` |
| `dns_error` | DNS не ответил или ответил ошибкой (`SERVFAIL`, `REFUSED`) и после второго прохода |
| `error` | прочее |

«Доступно» = `allow`, `allow_tls` или `open_http`. `http_redirect` в разрешённые не попадает: браузер уйдёт на https, который закрыт.

## Результат прогона

Без аргументов вывода создаётся каталог `<дата>_<время>_<оператор>` с тремя файлами:

```text
checks/
└── 2026-01-01_214500_megafon/
    ├── result.tsv           полный TSV со статусами
    ├── allow-domains.txt    домены, по одному в строке
    └── allow-ips.txt        IP, по одному в строке
```

- `allow-domains.txt` — домены со статусом `allow`, `allow_tls` или `open_http`, по одному в строке, без заголовка.
- `allow-ips.txt` — уникальные адреса, на которых прошло TLS-рукопожатие (`allow` / `allow_tls`), по одному в строке, отсортированы по возрастанию.

Имя оператора берётся из MCC/MNC (`25002` → `megafon`). Если оператор не определился — `unknown`; переопределяется через `WLP_OPERATOR`.

Каталог создаётся в `checks/` в корне проекта, а если инструмент скопирован отдельно (нет `src/` и `tools/` рядом) — в `./checks` от текущего каталога. Переопределяется через `--outdir DIR` или `WLP_OUTDIR`. При неудачном запуске пустой каталог удаляется.

Если задан любой из `-o`, `--allow-out`, `--deny-out`, `--domains-out`, `--ips-out`, автоматический каталог не создаётся — файлы пишутся ровно туда, куда сказано:

```bash
./whitelist-probe check -o result.tsv       # только TSV, без каталога
./whitelist-probe check -o -                # TSV в stdout
./whitelist-probe check --outdir /tmp/runs  # каталог со штампом в другом месте
./whitelist-probe check --domains-out allow-domains.txt --ips-out allow-ips.txt
```

Если вход был списком IP (`--kind ips`), `allow-domains.txt` будет пустым, а `allow-ips.txt` содержит прошедшие адреса.

### Формат TSV

```text
input  kind  status  checked_ip  all_ips  reason  ms  source  allowed_ips
```

- `input` — проверенное значение (домен в punycode или IP);
- `source` — имя файла, откуда пришло значение; пусто для stdin;
- `checked_ip` — адрес, на котором остановилась проверка;
- `all_ips` — все адреса домена, которые были проверены;
- `allowed_ips` — все адреса, где прошло TLS-рукопожатие (по умолчанию их может быть несколько);
- `reason` — текст ошибки, `HTTP 302 -> http://access.rt.ru/` и т. п.; если были повторы, добавляется `; попыток: N`.

Каталоги читаются рекурсивно, имя файла попадает в колонку `source` — так сохраняется разбивка по категориям. Одинаковые значения (после нормализации IDN и URL) проверяются один раз.

### Оговорки

- адреса доменов со статусом `open_http` и `http_redirect` в `allow-ips.txt` не попадают: на 443 они не работают, по 80 — работают. Если нужен список «отвечает хоть как-то», используйте `result.tsv` и фильтр по `$3`.
- `--first-ip` даёт по одному IP на домен; по умолчанию в файл попадают все адреса, где прошло TLS-рукопожатие (см. [Как это работает](#как-это-работает)).
- полный перебор A-записей медленнее: на домен тратится столько попыток, сколько у него адресов, а неудачные попадают во второй проход и повторяются там (`--retries`). Надёжнее запускать без `--jobs` (последовательно) и не прерывать.

### Из готового result.tsv

Те же списки из готового `result.tsv`, без повторной проверки:

```bash
awk -F'\t' 'NR>1 && $2=="domain" && ($3=="allow"||$3=="allow_tls"||$3=="open_http"){print $1}' result.tsv > allow-domains.txt
awk -F'\t' 'NR>1 { n=split($9, a, " "); for (i=1;i<=n;i++) if (a[i] != "") print a[i] }' result.tsv \
  | sort -u -t. -k1,1n -k2,2n -k3,3n -k4,4n > allow-ips.txt
```

Колонка `$9` (`allowed_ips`) содержит все подтверждённые адреса строки — их и берёт второй фильтр.

## Объединение прогонов

Отдельный инструмент `tools/whitelist-merge` смотрит в `checks/` и оставляет то, что разрешено **во всех** прогонах:

```bash
tools/whitelist-merge/whitelist-merge            # все прогоны из checks/
tools/whitelist-merge/whitelist-merge --dry-run  # только посчитать
```

Результат:

```text
release/
├── whitelist-common.txt        домены, разрешённые во всех прогонах
└── IP-whitelist-common.txt     IP, разрешённые во всех прогонах
```

Правила:

- источник — `result.tsv` прогона; домен считается разрешённым при статусе `allow`, `allow_tls` или `open_http`, IP — только `allow` / `allow_tls` (колонка `allowed_ips`);
- если `result.tsv` нет, берутся `allow-domains.txt` и `allow-ips.txt`;
- каждый прогон учитывается один раз, повторы внутри прогона не влияют;
- каталоги без данных пропускаются с предупреждением.

Опции: `--checks DIR`, `--out DIR` (или `WLP_CHECKS`, `WLP_RELEASE`). Можно передать конкретные каталоги аргументами вместо `checks/`:

```bash
tools/whitelist-merge/whitelist-merge checks/2026-01-01_220011_unknown checks/2026-01-01_101500_megafon
```

## Сеть и маршруты

Если сеть `WLP_NETWORK` не задана, инструмент ищет существующую macvlan-сеть с тем же parent-интерфейсом и подсетью (например, `modem-macvlan`) и переиспользует её. Если такой нет — создаёт `whitelist-macvlan-<iface>`. Это важно: docker не даёт создать вторую сеть с той же подсетью.

Шлюз находится сам и у USB-модема (`.1`), и у телефона в режиме USB-модема (обычно `.129`): сначала из DHCP/NetworkManager, затем перебором типовых адресов.

Оператор, сеть и сигнал:

```bash
./whitelist-probe operator
```

### Своя сеть

Можно указать готовую сеть и не давать инструменту ничего создавать:

```bash
WLP_NETWORK=modem-macvlan ./whitelist-probe check list.txt
```

Если сеть указана, но её нет, скрипт попробует создать её с подсетью, вычисленной из интерфейса.

### Что создаётся и что остаётся

Контейнеры запускаются с `--rm` и после проверки исчезают. Остаются только docker-сеть и образ:

- сеть — по одной на интерфейс, имя `whitelist-macvlan-<iface>` (или найдённая готовая);
- образ `whitelist-probe:latest` (~170 МБ). Первый запуск соберёт его (alpine + python3 + bind-tools + curl_cffi), дальше он переиспользуется.

Сама сеть — не настройка, а разовый объект: её можно удалить в любой момент между запусками, при следующем `check` она создастся заново.

Посмотреть:

```bash
docker network ls --filter driver=macvlan

# подробности: родительский интерфейс, подсеть, шлюз
docker network inspect whitelist-macvlan-enp3s0f3u2

# кто сидит в сети (во время проверки там один контейнер)
docker ps -a --filter network=whitelist-macvlan-enp3s0f3u2
```

Удалить:

```bash
docker network rm whitelist-macvlan-enp3s0f3u2
```

Все macvlan-сети сразу:

```bash
docker network ls --filter driver=macvlan -q | xargs -r docker network rm
```

Если docker отвечает `network is in use`, сначала найдите и снимите контейнеры:

```bash
docker ps -aq --filter network=whitelist-macvlan-enp3s0f3u2 | xargs -r docker rm -f
```

### Утечка трафика через модем

Проверки идут через `macvlan`-контейнер и от маршрутов хоста не зависят. Но сам хост при подключённом модеме может пустить весь трафик через него: DHCP модема ставит маршрут по умолчанию с метрикой 100, а Wi-Fi — 600, поэтому побеждает модем.

Проверить:

```bash
./net-guard status
```

```text
маршрут по умолчанию:
  default via 192.168.8.1 dev enp3s0f3u1u3 proto dhcp src 192.168.8.100 metric 100
  default via 192.168.1.120 dev wlp1s0 proto dhcp src 192.168.1.130 metric 600
внешний адрес пойдёт через: enp3s0f3u1u3

проблема: трафик хоста идёт через модем enp3s0f3u1u3
```

Исправить (через NetworkManager, настройки сохраняются после переподключения):

```bash
./net-guard fix
```

Что меняется в соединении модема:

- `ipv4.never-default yes` — модем не поставляет маршрут по умолчанию;
- `ipv4.route-metric 1000` — на случай, если маршрут всё же появится;
- `ipv4.ignore-auto-dns yes` — DNS хоста остаётся на Wi-Fi;
- `ipv6.never-default yes` — то же для IPv6.

Модем при этом остаётся доступен по своей подсети: `192.168.8.1`, определение оператора и сами проверки работают как раньше.

Откатить: `./net-guard revert`.

Важно: `fix` переподключает интерфейс модема. Не запускайте его во время проверки — текущий прогон может получить ложные таймауты.

Если NetworkManager не используется, `net-guard fix` покажет команду для `ip route del` (нужен `sudo`, действует до переподключения). Чтобы навсегда — отключите получение маршрута по умолчанию в DHCP этого интерфейса.

### Если что-то не так

| Симптом | Причина и решение |
| --- | --- |
| `Pool overlaps with other one on this address space` | уже есть сеть с такой подсетью. Это нормально: скрипт должен был её найти. Если сеть «чужая», удалите её или задайте `WLP_NETWORK` |
| `no matching subnet for gateway ...` | `--gateway` не входит в подсеть интерфейса — проверьте адрес модема |
| Контейнер не стартует, код 125 | адрес `.250–.253` занят или не подходит. Скрипт перебирает `.250–.253`, можно задать свой: `--container-ip` |
| Сеть осталась после отключения модема | она привязана к исчезнувшему интерфейсу, но безвредна. Удаляется обычным `docker network rm` |
| `network id "..." not found` при создании endpoint | docker потерял состояние macvlan-сети (после перезапуска docker или переподключения модема): сеть видна в `docker network ls`, но её id не резолвится. Скрипт пересоздаёт свою сеть сам; вручную — `docker network rm whitelist-macvlan-<интерфейс>` и повторный запуск |
| Проверка идёт, но всё «разрешено» | скорее всего трафик ушёл через обычный интернет. Проверьте строку `== USB-интерфейс: ...` в выводе и `doctor` |
| Фоновый трафик уходит в модем | DHCP модема даёт маршрут по умолчанию с метрикой 100, Wi-Fi — 600. Лечится `net-guard fix`, см. выше |

## Справочник

### Что проверять

| Опция | По умолчанию | Смысл |
| --- | --- | --- |
| `--kind auto\|domains\|ips` | auto | как трактовать входные строки |
| `--max-ips N` | все | ограничить число проверяемых адресов |
| `--first-ip` | — | остановиться на первом рабочем адресе, по одному IP на домен |
| `--all-ips` | включено | перебирать все A-записи (оставлено для совместимости) |
| `--no-http80` | — | не проверять порт 80 |
| `--no-second-pass` | — | только первый проход, без медленных повторов TLS |
| `--max-cidr N` | 1024 | предел адресов в одном CIDR; крупнее — пропуск |
| `--dry-run` | — | только показать список целей, без проверки; модем и docker не нужны (нужен `python3`, без него — образ с `--network none`) |

### Как проверять

| Опция | По умолчанию | Смысл |
| --- | --- | --- |
| `--sni NAME` | `gosuslugi.ru` | SNI/Host для проверки IP |
| `--timeout SEC` | 8 | таймаут соединения |
| `--retries N` | 2 | медленных повторов TLS во втором проходе (`0` — без второго прохода) |
| `--delay SEC` | 0.3 | пауза между целями (`0` — без паузы) |
| `--jobs N` | 1 | параллельность; **больше 1 даёт ложные блокировки** |
| `--portal-host H` | `access.rt.ru` | домен страницы блокировки |

### Куда писать

| Опция | По умолчанию | Смысл |
| --- | --- | --- |
| `-o, --out FILE` | каталог со штампом | куда писать TSV (`-` — в stdout) |
| `--outdir DIR` | `checks/` в корне проекта | куда создавать каталог со штампом |
| `--allow-out FILE` | — | только разрешённые значения |
| `--deny-out FILE` | — | только заблокированные |
| `--domains-out FILE` | — | разрешённые домены, по одному в строке |
| `--ips-out FILE` | — | IP, на которых проверка прошла, по одному в строке |

### Подключение

| Опция | По умолчанию | Смысл |
| --- | --- | --- |
| `--iface NAME` | авто | интерфейс модема |
| `--gateway IP` | авто | шлюз модема |
| `--subnet CIDR` | авто | подсеть macvlan |
| `--container-ip IP` | авто | адрес контейнера |

Справка по всем командам: `./whitelist-probe -h`.

### Примеры

```bash
./whitelist-probe check -o result.tsv list.txt        # только TSV, без каталога
./whitelist-probe check --dry-run                     # только показать цели
./whitelist-probe check --kind ips ips.txt            # список IP и CIDR
./whitelist-probe check --first-ip ../../src/domains  # быстрее, один IP на домен
```

### Входные данные

Вход читается из файлов и/или stdin (`-`). Пустые строки и `#` игнорируются. Можно передавать URL — инструмент выделит хост. IDN-домены переводятся в punycode.

В `--kind ips` принимаются одиночные IPv4 и CIDR (до `--max-cidr`, по умолчанию 1024 адреса).

### Переменные окружения

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `WLP_IMAGE` | `whitelist-probe:latest` | образ для проверки |
| `WLP_NETWORK` | находится или создаётся | готовая macvlan-сеть |
| `WLP_GATEWAY` | `192.168.8.1` | шлюз модема |
| `WLP_OUTDIR` | `checks/` в корне проекта | куда создавать каталог прогона |
| `WLP_OPERATOR` | из MCC/MNC | имя оператора в имени каталога |
| `WLP_CHECKS` | `checks/` проекта | откуда `whitelist-merge` берёт прогоны |
| `WLP_RELEASE` | `release/` проекта | куда `whitelist-merge` пишет результат |
